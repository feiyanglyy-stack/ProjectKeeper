# Code-map counting rules

`CodeMapIndex` takes the existing ledger and the project's stored work items and territories. It does not invoke a model.

- **What counts as code:** the ledger decides, not a list of languages. A file is code when a reader reads its references (`code_files.reader`: the TypeScript compiler for TypeScript and JavaScript, the code engine for every other language), or when it is in a language the ledger knows is code though nothing reads it (anything but the prose and data of `ledger/code.ts` `NOT_CODE`: a shell script, a C header with nothing in it to read, any code when the engine cannot run). Generated, classified (third-party) and test files are no territory's code. `Ledger.referenceReach` weighs a residual judgement by the same rule. A ledger built before the `reader` column existed has none; TypeScript and JavaScript then count as read, as the ledger itself falls back.
- **Built by:** only commits on the trunk's first-parent line count. A merge's `commit_files` already means its diff against its first parent; each commit's changed path counts once. A retained fast-forward branch can name the contiguous first-parent run back to the preceding merge or another known work item. Commit message and branch identifiers match `WorkThread.ids` and `KeeperNumber` aliases. A confirmed `ProcessLink` to `commit:<hash>` overrides a textual match. Rows without a unique work match remain `Unclaimed`. A deleted branch with no identifying commit text or confirmed link cannot be recovered from the current refs.
- **Generation:** the rebuild runs read-only `git blame --incremental` on the current HEAD's unclassified, non-generated files whose references a reader reads (`ledger/blame.ts`); code nothing reads is not blamed and adds no lines to a generation. The ledger stores ranges of line numbers and commit hashes, keyed by each file's git blob id. Unchanged blobs reuse the cache. A date-only `Generation.ended` includes that local author day; a timestamp uses its exact instant. Lines after all ended generations belong to the current generation (`generationId: null`). `generationOrigins()` gives the line count, share and work breakdown; `TerritoryView.generations` carries each share and the work items its lines came from.
- **Dependency count:** one edge per distinct source-file/target-file pair crossing two territories. Every non-test kind `code_deps` records counts — the compiler's `import` and `reference`, the engine's `import`, `calls` and the other references it resolved — and duplicate kinds for the same pair count once. External packages and test-file edges do not count.
- **Current use:** every code file takes part. Tests and generated/classified files cannot keep a source file live. Conventional `main`, `app`, `index`, `cli`, `bootstrap`, `application`, `route` and `router` files and files changed by a work item in the current generation anchor a non-test reference walk; a reference from code a reader reads can reach code nothing reads. Code outside that closure is unreferenced, including chains and isolated cycles. Who names such code comes from the ledger (`code_files.named_by`, `ledger/code.ts` `NamingKind`), read from every tracked text file: a build or manifest file naming it (a C++ source its `CMakeLists.txt` compiles, the activity `AndroidManifest.xml` launches by `.MainActivity`) makes it a named entry point; code the walk reaches naming it, a reference its reader did not resolve (a Dart `part`); a document, data or a test's fixture only mentions it. A named entry point, a file live code names, and code only they reach are not shown to be unreferenced. A territory none of whose code is reached is `Unreferenced` when some of it is read and none of it is such code, and `Not known` otherwise, as is a territory with no code. A territory whose live incoming references all come from files with at least 95% older-generation lines is `Previous generation only`; otherwise it is `In current plan` when current work changed it or its area has requirements, designs, decisions, plans or work items in force, else `In use, not in current plan`. These are program candidates from file references, not proof of runtime use or a plan link. Dynamic registration, routing, reflection and manually invoked scripts need model review. An unreferenced candidate says what is uncertain about it — nothing reads it; it is a named entry point, "named in AndroidManifest.xml"; code names it; only such files reach it — and its judgement is then `Inferred` (`Ledger.referenceReach`); a mention is said too and leaves it computed.
- **Residual-name candidates:** a path component or token `legacy`, `old`, `deprecated`, `backup` or `v1` with a non-test inbound reference. Generic words only: whether a project's own name looks residual (a folder still called after the product's first idea) is the cross-check's judgement from that project's history. This is a naming heuristic, never an anomaly judgement.
- **How deep each language is read:** `codeLevels()` gives `CodeView.levels` from the ledger's measured coverage (`Ledger.coverage().languages`): every language a reader reads and every language the ledger knows is code — who reads it, how many of its files, and for the engine the imports it resolved to a repository file and those it left unresolved naming one, the files code names that no counted reference reaches, and parse errors. A language is `complete` when every file is read and nothing was measured unresolved; elsewhere residual calls are `Inferred`. Named entry points say where a language's code is entered, not how deep it is read: the ledger's coverage counts them apart (`namedEntryPoints`), and a residual call on one is `Inferred` by `Ledger.referenceReach`. `Project scope` says the same per language from the same data (`ScopeKView` `ledger.languages[].code`, `ledger/views.ts` `coverageView`).

The model-owned `CodeTerritory.anomalies` is unchanged. `codeAnomalyCandidates(ledger, store, project)` supplies cross-check input with ledger file and commit references. With no territories yet, `codeView()` displays measured disjoint directories under their real paths and the message `No territories drawn yet`.
